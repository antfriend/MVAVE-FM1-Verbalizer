# Porting notes

What has been ported, how it is checked against the original, and where the C code knowingly differs.

## The vocal tract is bit-exact, and how we know

[tools/pasm_ref.py](../tools/pasm_ref.py) assembles the DAT section of the original `VocalTract.spin` and executes it instruction by instruction in a small model of a Propeller cog, self-modifying code included. It plays the scripts in [tests/golden](../tests/golden) and records a hash of every sample in `hashes.txt`. The C test suite plays the same scripts through `vocal_tract.c` and must produce the same hashes.

The four scripts cover voiced sound with vibrato, both noise sources, the nasal branch, queue overflow and underrun, pace, attenuation, every parameter at 0 and 255, and deliberate numerical overflow. All 24,418 samples match.

The reference is the original's source text run by an emulator written for this project. It has not been compared with a recording of real hardware, which is still worth doing once.

To regenerate the hashes after adding a script (about 800 samples a second):

```
python tools/pasm_ref.py --spin path/to/VocalTract.spin --update tests/golden
```

`VocalTract.spin` is not kept in this repository. It is in [antfriend/Verbalizer](https://github.com/antfriend/Verbalizer).

The two lookup tables were checked word for word against the ROM image published in [parallaxinc/Propeller_1_Design](https://github.com/parallaxinc/Propeller_1_Design) (`hub_rom_high.hex`). Both are plain rounding of the textbook formulas, so the generator needs no ROM file.

## How the tract keeps time

Worth knowing before touching the sample rate.

- The tract makes one sample per pass of its loop, at 20 kHz. Its frame handler is a coroutine that does one small piece of work per sample.
- A glide step takes 14 samples (700 µs): one sample of set-up and one for each of the 13 parameters, which are therefore updated one after another, not together.
- A frame of *n* steps lasts exactly 14 × *n* samples. The first 14 compute the per-step increments; the remaining *n* − 1 steps apply them.
- When the queue is empty the tract snaps each parameter onto its target, one per sample, then looks for a new frame every 14 samples.
- The output is the previous pass's value, so there is one sample of latency.

## Sample rate

The tract runs at 20 kHz and nothing in it is parameterised by rate. Formant and nasal frequencies, the resonator damping, pitch tuning, vibrato rate, noise colour and all glide timing depend on that number. Changing any of it would give up bit-exactness.

So the engine stays at 20 kHz and its output is resampled to the FM-1's rate, which is fixed at 44.1 kHz. The ratio is exactly 441/200.

[engine/resampler.c](../engine/resampler.c) is a 16-tap polyphase FIR in integer arithmetic: a Kaiser-windowed sinc tabulated at 64 positions per input sample and interpolated between them. It is flat to 7 kHz, 1 dB down at 8 kHz and 6 dB down at 9.2 kHz, and the images of anything below 8 kHz are more than 64 dB down. It adds 0.4 ms of delay and costs 32 multiplies per output sample, small beside the tracts. A constant input comes out exact, so silence stays silence. The table is generated by [tools/gen_resampler.py](../tools/gen_resampler.py), which can also print the response.

The top of the band is the compromise: the tract's own output reaches 10 kHz, and the last 2 kHz of it is rolled off to keep the images out. The original's output filter was a resistor and a capacitor on a pin, so nothing audible depended on that octave being flat.

## Deliberate differences

**`go` does not block.** The Spin `go` waited until one of eight frame buffers was free, stalling the whole main loop, key scanning included. Here the queue holds 32 frames and `vt_go` returns `false` when it is full. Ordinary playing queues at most 25 frames at once, and the tests check that none are dropped. `vt_full` still reports "8 or more queued" for code that wants the original's pacing.

**Key handling is event-driven.** The original scanned a key matrix every 2 ms or so and derived trigger, sustain and release states from it. The engine takes key-down and key-up calls, keeps the same states, and runs the same per-mode logic every 40 samples (2 ms). A key pressed and released inside one 2 ms window, which the original missed, is played as the shortest possible note.

**Formants mode pacing.** The original queued eight frames for every held key on every pass and let the blocking `go` set the pace. The engine queues a key's frames when voice 0 has run dry and takes held keys in turn. Knob changes are heard sooner as a result.

**Mode changes clean up.** Changing mode releases all keys and fades all voices. On the original, flipping the switch during a note could leave it sounding.

**Keys outside 1–37.** Pitch is clamped to the tract's range and the volume back-off cannot go negative. Keys 1–37 behave as before.

**Voices' noise is decorrelated.** Each tract's noise generator is advanced by a different amount at start-up. On the Propeller the four cogs started at different times; in C they would otherwise produce identical noise.

**Mono, with a soft limit.** The four voices are summed. Up to half of full scale the sum passes through untouched, so a single voice plays at its own level; above that it is squeezed smoothly towards full scale and never clips hard. This is a placeholder for the spatializer, which also provided the echo.

**Voices start on a neutral vowel.** A new tract has its formants at 0 Hz, where the resonators have enormous gain, and the original's first note on each voice swept up from there with the sound already on. Each voice now parks its formants at 500, 1500, 2500 and 3500 Hz while still silent.

**Silence is exactly zero.** The resonators' integer rounding leaves them stuck a few counts below zero after a sound dies away. The instrument clears that residue (`vt_settle`) once a voice is silent, so the output returns to 0 and the firmware can tell when nothing is playing. The tract on its own does not do this.

**Velocity, pitch bend, sustain pedal, MIDI controllers.** New; see [midi.md](midi.md).

## Corrected bugs

Four bugs in `Voice.spin` are fixed, so the port sounds different from the original where they applied.

- **Vowel table.** Phonemes 9–19 were converted with the wrong divisor and wrapped in a byte, which put them about 1.6 times too high with a wrapped f4. They now use the tract's real units. See [phonemes.md](phonemes.md).
- **Closing fade.** The fade used by Words and Formants modes looked up a phoneme with the release *time* knob, so that knob could bend the formants during the fade or even start a word. The fade now only drops to key 1's pitch and goes silent. With that knob below 21 nothing has changed.

- **Volume back-off.** Glottal amplitude is reduced by `key / 2` to keep higher notes from overflowing. The original only did this when the requested amplitude was larger than `key / 2` and otherwise used it as it was, so on key 13 a volume of 7 gave 1 while a volume of 6 gave 6. Now the reduction always applies and stops at zero. The cost is a dead zone at the bottom of the volume knobs that grows with pitch.

- **Frication and nasal settings stuck to a voice.** Nothing in Trigger / Sustain / Release mode ever turned frication off, so a voice that had played the noise phoneme hissed from then on, key up or down. The nasal settings of "ah" and of the word lingered the same way. Now every phoneme starts with both off, and silence turns frication off.

## The crackle

The Propeller tract's arithmetic wraps on overflow. When a voice is driven too hard, usually by too much volume for the formants in use, the wrap is heard as bursts of loud noise. On the original the volume knobs were the only cure.

The tract now has a second mode, `vt_set_saturate`, in which it clips instead. The sums into the four resonators, the nasal branch and the frication are saturating adds, and a resonator whose input has been clipped is rotated in 64 bits so that the rotation cannot wrap either. Nothing else changes, so a sound that never overflowed comes out bit for bit the same in both modes; the tests check this. An overdriven sound becomes a clipped, buzzy version of itself in place of noise.

- `vocal_tract` on its own still starts in the original's wrapping mode, which is what the golden tests compare against the Propeller assembly.
- The instrument turns saturation on for all four voices. `vb_set_crackle(vb, true)` restores the original behaviour, and score files can say `crackle on`.

Things that still overflow by design: the oscillator phases, and glottal pitch plus deep vibrato at the very top of the pitch range, which wraps to a low pitch as before.

- Everything listed under "Not yet known" in [fm1-platform.md](fm1-platform.md).
- CPU load of four tracts on the AC791N. Per voice, each sample runs five CORDIC rotations of 14 shift-and-add steps and five small multiplies.
- Whether to port the spatializer or use something lighter for stereo and echo.
- The cost of the saturating mode on the AC791N. It adds a 64-bit add and compare at ten places per voice per sample, and a 64-bit rotation only while a voice is actually clipping.
