What has been ported, how it is checked against the original, and where the C code knowingly differs.

## The vocal tract is bit-exact, and how we know

[tools/pasm_ref.py](../tools/pasm_ref.py) assembles the DAT section of the original `VocalTract.spin` and executes it instruction by instruction in a small model of a Propeller cog, self-modifying code included. It plays the scripts in [tests/golden](../tests/golden) and records a hash of every sample in `hashes.txt`. The C test suite plays the same scripts through `vocal_tract.c` and must produce the same hashes.

The four scripts cover voiced sound with vibrato, both noise sources, the nasal branch, queue overflow and underrun, pace, attenuation, every parameter at 0 and 255, and deliberate numerical overflow. All 24,418 samples match.

The reference is the original's source text run by an emulator written for this project. It has not been compared with a recording of real hardware, which is still worth doing once.

To regenerate the hashes after adding a script (about 800 samples a second):

```
python tools/pasm_ref.py --spin path/to/VocalTract.spin --update tests/golden
```

`VocalTract.spin` is not kept in this repository. It is in [antfriend/Verbalizer](https://github.com/antfriend/Verbalizer).

The two lookup tables were checked word for word against the ROM image published in [parallaxinc/Propeller_1_Design](https://github.com/parallaxinc/Propeller_1_Design) (`hub_rom_high.hex`). Both are plain rounding of the textbook formulas, so the generator needs no ROM file.

## How the tract keeps time

Worth knowing before touching the sample rate.

- The tract makes one sample per pass of its loop, at 20 kHz. Its frame handler is a coroutine that does one small piece of work per sample.
- A glide step takes 14 samples (700 µs): one sample of set-up and one for each of the 13 parameters, which are therefore updated one after another, not together.
- A frame of *n* steps lasts exactly 14 × *n* samples. The first 14 compute the per-step increments; the remaining *n* − 1 steps apply them.
- When the queue is empty the tract snaps each parameter onto its target, one per sample, then looks for a new frame every 14 samples.
- The output is the previous pass's value, so there is one sample of latency.

## Sample rate

The tract runs at 20 kHz and nothing in it is parameterised by rate. Formant and nasal frequencies, the resonator damping, pitch tuning, vibrato rate, noise colour and all glide timing depend on that number. Changing any of it would give up bit-exactness.

So the engine stays at 20 kHz and the firmware will resample its output to the FM-1's rate. That resampler is not written yet. 20 kHz to 44.1 kHz is a ratio of 441/200. 20 kHz to 48 kHz is 12/5, which is simpler if the FM-1 codec can run at 48 kHz.

## Deliberate differences

**`go` does not block.** The Spin `go` waited until one of eight frame buffers was free, stalling the whole main loop, key scanning included. Here the queue holds 32 frames and `vt_go` returns `false` when it is full. Ordinary playing queues at most 25 frames at once, and the tests check that none are dropped. `vt_full` still reports "8 or more queued" for code that wants the original's pacing.

**Key handling is event-driven.** The original scanned a key matrix every 2 ms or so and derived trigger, sustain and release states from it. The engine takes key-down and key-up calls, keeps the same states, and runs the same per-mode logic every 40 samples (2 ms). A key pressed and released inside one 2 ms window is missed, as it was on the original.

**Formants mode pacing.** The original queued eight frames for every held key on every pass and let the blocking `go` set the pace. The engine queues a key's frames when voice 0 has run dry and takes held keys in turn. Knob changes are heard sooner as a result.

**Mode changes clean up.** Changing mode releases all keys and fades all voices. On the original, flipping the switch during a note could leave it sounding.

**Keys outside 1–37.** Pitch is clamped to the tract's range and the volume back-off cannot go negative. Keys 1–37 behave as before.

**Voices' noise is decorrelated.** Each tract's noise generator is advanced by a different amount at start-up. On the Propeller the four cogs started at different times; in C they would otherwise produce identical noise.

**Mono.** The four voices are summed, halved and clipped. This is a placeholder for the spatializer, which also provided the echo.

## Kept quirks

These look like bugs and are reproduced on purpose. See also [phonemes.md](phonemes.md).

- The table vowels (phonemes 9–19) use the wrong frequency divisor and wrap in a byte.
- The closing fade picks its phoneme with the release *time* knob.
- Glottal amplitude is reduced by `key / 2`, but only when the requested value is larger than that.
- Overflow in the tract wraps instead of clipping. This is the "crackle", and the volume knobs are how a player tames it.

## Open questions for the firmware stage

- Which sample rates the FM-1's audio path offers, and the cost of resampling there.
- CPU load of four tracts on the AC791N. Per voice, each sample runs five CORDIC rotations of 14 shift-and-add steps and five small multiplies.
- Whether to port the spatializer or use something lighter for stereo and echo.
- The optional saturation in place of the crackle. It can clip the final mix cheaply, but true saturation inside the tract changes the resonators' behaviour and would need its own listening tests.
